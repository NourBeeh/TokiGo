## Scope and method

- **Android platform**: every NVD CVE whose CPE is `cpe:2.3:o:google:android`, intersected with the API levels TokiGo declares (`minSdk` / `targetSdk`).
- **TokiGo dependencies**: exact resolved versions from `pubspec.lock`, `backend/package-lock.json`, and the pinned Android build toolchain (AGP, Kotlin, Gradle). Each npm/pub component is tagged `prod` or `dev` (build/CI/test only) from the lockfile `dev` flag.
- **Known exploited**: CISA KEV catalog, matched by CVE id or OSV alias.
- `platform-unconfirmed` means NVD gives no version range for the CVE; treat as *assume affected until the device patch level is verified*.

## Recommended actions

1. **Production (runtime) findings first** — fix the server-side packages: `proxy-addr` (critical), `multer`/`body-parser` via `@nestjs/platform-express`, `lodash` via `@nestjs/config`, plus `qs`, `file-type`, `uuid`, `brace-expansion`, `glob`/`minimatch`/`typeorm`. `npm audit fix` in `backend/` resolves what stays semver-compatible, but several fixes are NestJS major (12.x). Plan the upgrade and re-run this report with `npm test`.
2. **Dev/build-time findings can be deferred** — `handlebars`, `webpack`, `tmp`, `picomatch`, `js-yaml`, `jest` and friends do not ship in the APK, but they execute on developers' machines and in CI. Upgrade `@nestjs/cli` to >= 12.0.11 and the jest/ts-jest stack in a dedicated PR, then re-run the audit.
3. **Android platform is not fixable by app code** — the only real mitigation is an up-to-date device security patch. Enforce a minimum patch level in Play Console / MDM, and consider raising `minSdk` (currently 24) to exclude devices that can never receive fixes.
